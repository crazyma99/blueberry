## 1. Requirements (Context)

- **Goal**: 在现有客片浏览流程中嵌入 AI试衣入口，用户可通过上传照片 + 选择服饰模板，生成 AI 换装效果图，提升用户对服饰的直观感受和到店转化率
- **In-Scope**:
  - 客片列表（demoDetail）卡片右下角新增"AI试衣"标签按钮
  - 客片详情页（targetPhotoDetail）右下角新增悬浮"AI试衣"按钮
  - AI试衣配置选择页（服饰模板轮播 + 体型选择 + 年龄选择 + 照片上传 + 生成按钮）
  - AI试衣生成加载页（进度提示 + 取消返回）
  - AI试衣结果展示页（大图展示 + 保存到相册）
  - 生成失败处理（重试 + 3次失败限流提示）
  - 需登录后才能使用
- **Out-of-Scope**:
  - 后台管理配置（3.1.5 后台配置页面由后端/管理后台团队负责）
  - AI试衣历史记录页（确认本期不做）
  - 门店定位与就近排序功能
  - 埋点上报实现（接入时机另议）
  - 免费次数限制逻辑（后端控制）
  - 第三方 AI 方案对接（后端负责，前端接口占位）

## 2. Research Findings

### 事实与约束

**现有架构适配性：**

1. 客片列表（demoDetail）使用网格卡片布局，每张卡片底部已有标题+点赞数展示区，需在此区域右侧追加"AI试衣"标签按钮
2. 客片详情（targetPhotoDetail）当前无悬浮按钮，需新增 fixed 定位的悬浮按钮组件
3. "AI试衣"入口的显示条件依赖后台相册配置中的"支持AI试衣"标记字段（需接口返回此字段）
4. 项目技术栈：uni-app x + Vue 3 + UTS，目标平台 mp-weixin
5. 所有新页面需在 `src/pages.json` 注册路由
6. 照片上传使用 `uni.chooseImage` / `uni.chooseMedia`，上传至服务端使用 `uni.uploadFile`
7. 深色主题：页面背景 `#000`，与设计稿一致

**接口依赖分析：**

- 现有接口保持不动：`getAlbumList`、`getalbumDetail`、`toggleLike` 等均不修改
- AI试衣入口显示策略：本期默认展示（待后端提供 `supportAiTryOn` 字段后再改为条件控制）
- 新增接口（全部占位，待接口文档补齐后对接）：
  - `getAiTemplates(albumId)` — 获取相册关联的 AI 试衣模板列表
  - `submitAiTryOn(params)` — 提交 AI 试衣生成请求
  - `getAiTryOnResult(taskId)` — 轮询获取生成结果
  - `uploadPhoto(filePath)` — 上传用户照片
- 认证：AI试衣全链路需登录态

**UI 设计分析（基于截图）：**

- 客片列表入口：黑色圆角矩形标签"AI试衣"，位于卡片底部右侧，与点赞区并排
- 客片详情悬浮按钮：底部居中，胶囊形渐变按钮"AI试衣"
- 配置页布局：顶部服饰大图轮播 → 体型三选一 → 年龄下拉 → 照片上传区 → 底部固定生成按钮
- 生成页：简洁加载态，顶部标题"正在生成"，含"购买照片"按钮（可能为占位）

### 风险与不确定项

1. **第三方 AI 接口未确定**：接口方案待技术评审，当前只能预留接口层抽象，具体参数格式待对齐
2. **生成耗时较长（10-30秒）**：需考虑用户在等待期间退出页面后的状态处理
3. **照片隐私合规**：用户照片上传后服务端不做持久化存储，前端需做好提示
4. **图片大小限制**：单张不超过 10MB，前端需做校验和压缩

## 3. Innovate (Optional: Options & Decision)

### Option A: 独立页面方案（推荐）

AI试衣配置页 + 生成结果页作为独立的 uvue 页面，通过路由跳转串联。

- Pros: 代码隔离清晰，生命周期独立管理，符合现有项目"一页面一目录"规范
- Cons: 页面切换有短暂白屏（可接受）

### Option B: 弹窗/半屏方案

AI试衣配置在半屏弹窗中展示，不离开当前页面。

- Pros: 体验更流畅，不离开浏览上下文
- Cons: 半屏空间有限难以放下所有配置项；与现有项目架构模式不一致；轮播图展示受限

### Decision

- Selected: **Option A — 独立页面方案**
- Why: 配置项较多（轮播+体型+年龄+照片上传+生成按钮），需要完整页面空间；符合项目现有"每个功能一个页面目录"的架构规范；代码维护边界清晰
